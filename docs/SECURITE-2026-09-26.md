# Revue de sécurité — application mobile Switchboard (26/09/2026)

Dépôt `hobbitton-chat-android`, `develop` à `4c0c634` (D-071 fusionné). Deux
revues défensives en lecture seule, menées en parallèle sur le code partagé
(KMP), Android et iOS : **authentification et réseau** (jetons, OAuth du
portail, intercepteurs, redirections, trafic en clair, stockage, sauvegardes,
journaux, signature) et **contenu non fiable** (WebViews d'artefacts, liens,
partage entrant, fichiers, données après déconnexion, planificateur).
Pendant du second audit serveur (`hobbitton-chat-server`,
`docs/SECURITE-2026-09-26-bis.md`, D-075).

Aucun constat critique. Un constat élevé (C1). Les gravités suivent le
modèle de menace de l'app : un serveur ou un contenu de conversation hostile
(injection indirecte), une application tierce sur le même appareil, un réseau
non fiable.

---

## Résumé

1. **Les jetons tiennent.** LibreChat : `EncryptedSharedPreferences` sous
   clé Keystore, récupération en place, purge Room par compte, un seul
   rafraîchissement à la fois, 401 → session expirée. Portail : PKCE S256 et
   `state` aléatoires, PAR obligatoire, `verifier` jamais persisté. Moteur :
   fichier chiffré séparé, mot de passe jamais relu par l'interface.
2. **Ce qui manquait côté réseau** : le client du portail Authelia était le
   client LibreChat lui-même (bearer, en-têtes de passerelle, barrière de
   compte) ; les identifiants du moteur suivaient une redirection vers un
   hôte étranger ; le bearer LibreChat ne regardait que l'hôte (ni schéma,
   ni port, ouvert par défaut) ; `http://` accepté partout. **Corrigé.**
3. **Ce qui manquait côté contenu** : les artefacts HTML/React, Markdown,
   Mermaid et KaTeX tournaient dans des WebViews à origine réelle
   (`https://cdn.jsdelivr.net`), navigation libre, cookie jar commun au flux
   OAuth ; liens ouverts sans filtre de schéma ; partage entrant téléversé
   sans regarder l'URI. **Corrigé** (voir la section 2).
4. **Sauvegardes et journaux** : pas de `dataExtractionRules`, Logcat non
   rédigé en release, jetons iOS sans `ThisDeviceOnly`. **Corrigé.**

## 1. Authentification, réseau, plateforme

| # | Gravité | Constat | Statut |
|---|---|---|---|
| M1 | Moyenne | Le client OAuth du portail (Authelia) est le client HTTP de LibreChat : bearer, en-têtes de passerelle, barrière de compte et retry sur des appels qui transportent `code_verifier` et `refresh_token` du portail | **corrigé** : client nu `KoinQualifiers.Portal` (ContentNegotiation, garde du clair, timeouts), test de graphe `EnginePortalClientTest` |
| M2 | Moyenne | `Authorization: Basic` et `Proxy-Authorization: Bearer` (moteur, planificateur) posés sur toute requête, recopiés par Ktor sur une redirection inter-autorité | **corrigé** : posés seulement sur l'autorité exacte du service, retirés et réappliqués à chaque saut (`EngineAuthPlugin`, 8 cas de test) |
| M3 | Moyenne | Bearer LibreChat borné à l'hôte seul, ouvert par défaut ; `downloadFromUrl` sur une URL absolue du serveur | **corrigé** : `isSameServerAuthority` (schéma + hôte + port, fermé par défaut) pour l'attache et le retry ; `isSameHostAsServer` supprimé |
| M4 | Moyenne | Trafic en clair autorisé globalement | **corrigé, borné** : `CleartextPolicy` (bouclage, RFC 1918, CGNAT, link-local, ULA, `.local` et assimilés) appliquée à la saisie et par `CleartextGuardPlugin` sur les six clients ; `cleartextTrafficPermitted` reste `true` dans la ressource Android, qui ne sait pas exprimer une plage d'adresses (documenté dans le XML) |
| M5 | Moyenne | `allowBackup=false` sans `dataExtractionRules` (transfert d'appareil sur 12+) | **corrigé** : `data_extraction_rules.xml` exclut la base Room, `librechat_tokens`, `engine_secrets`, `datastore/`, `diag_logs/` du cloud et du transfert ; test |
| M6 | Moyenne | WebView d'artefacts (doublon de C1) | **corrigé**, voir section 2 |
| F1 | Faible | Logcat non filtré en release ; iOS en `Debug` toujours | **corrigé** : `RedactingLogWriter` (WARN et rédaction en release), iOS selon le binaire |
| F2 | Faible | Analyseurs SSE/HTTP sans borne mémoire | ouvert (voir section 4) |
| F3 | Faible | Keychain iOS sans `ThisDeviceOnly` | **corrigé** : `AfterFirstUnlockThisDeviceOnly` pour les jetons, `server_url` inchangé |
| F4 | Faible | Release signée avec la clé de débogage publique en l'absence de keystore | ouvert (voir section 4) |
| F5 | Faible | Moteur, émetteur et planificateur acceptés en `http://` | **corrigé** : `https://` exigé hors hôte privé, message localisé |
| I1–I5 | Info | Boîte du rappel OAuth, jeton OAuth via `CookieManager`, `security-crypto` déprécié, `tempToken` 2FA dans l'état sauvegardé, UA Chrome | notés, sans action |

## 2. Contenu non fiable, WebView, fichiers, données

| # | Gravité | Constat | Statut |
|---|---|---|---|
| C1 | Élevée | Artefacts HTML/React exécutés avec l'origine réelle `cdn.jsdelivr.net`, navigation et formulaires libres, `localStorage` partagé, cookie jar commun au flux OAuth | **corrigé** : `LockedDownWebView` (origine opaque, `domStorage` off, toute navigation refusée, politique de ressources native : jamais de cadre principal, sous-ressources `https` des seuls hôtes du gabarit) ; HTML/React confinés dans une `<iframe sandbox="allow-scripts" srcdoc>` (ni formulaires, ni popups, ni navigation) ; `ArtifactIsolationTest`, `WebResourcePolicyTest` |
| C2 | Moyenne | CSP en `<meta>` insérée dans un document contrôlé par le contenu : contournable | **corrigé** : la CSP reste (durcie : `form-action`, `base-uri`, `object-src 'none'`), mais la frontière est le sandbox et la politique native, plus la meta |
| C3 | Moyenne | Markdown et Mermaid injectés dans un littéral JS, HTML non assaini, `securityLevel: 'loose'`, pont JS exposé | **corrigé** : contenu transporté en base64 (jamais dans un littéral JS), DOMPurify avant `innerHTML`, Mermaid `strict`, SVG du pont validé (`<svg` en tête, taille bornée, sans script ni gestionnaire d'événement) |
| C4 | Moyenne | KaTeX `trust: true`, WebView LaTeX sans contrôle de navigation | **corrigé** : `trust: false`, client verrouillé, CSP et SRI |
| C5 | Moyenne | Liens ouverts par `ACTION_VIEW` sans filtre de schéma (messages, citations, agents, MCP) | **corrigé** : `SafeUriHandler` (http, https, mailto) posé à la racine, `PlatformUri` limité à otpauth/http/https ; `SafeUriHandlerTest` |
| C6 | Moyenne | Partage entrant : URI non filtrées (`file://`, propre FileProvider), téléversées à la réception | **corrigé** : `content://` seulement, propre FileProvider exclu, 20 éléments au plus, mise en attente jusqu'au bouton « Joindre » ; `FileAttachmentDelegate` refuse tout autre schéma ; `SharedUriPolicyTest` |
| C7 | Moyenne | Bearer sur le même hôte quel que soit le schéma ou le port ; images du modèle chargées par le client authentifié | **corrigé** : bearer borné à l'autorité exacte (voir M3) ; `image_url` hors origine du serveur chargée par un loader sans jeton (`UnauthenticatedImageLoader`, `UrlOriginTest`) |
| C8 | Moyenne | Scripts de CDN non épinglés, sans `integrity` | **corrigé, avec deux réserves** : versions épinglées et `integrity` sha384 pour mermaid, marked, DOMPurify, highlight.js, KaTeX, Babel ; Tailwind épinglé sans SRI (l'hôte ne sert pas de CORS) et les modules `esm.sh` non vérifiables |
| C9 | Faible | Raccourcis d'artefacts, cache disque Coil et cache WebView survivent à la déconnexion | **corrigé** : la purge de compte efface les raccourcis d'artefacts et le cache WebView ; le cache Coil l'était déjà à tout changement d'identité ; `AccountDataPurgerTest` |
| C10 | Faible | Décodage JSON-RPC du planificateur : exceptions non typées sur une réponse inattendue | **corrigé** : le décodage ne lève plus que `EngineHttpException` (7 cas de test) |
| C11 | Faible | Règles de permission construites depuis le catalogue serveur sans garde-fou sur les motifs (`*`) | **corrigé** : motif vide, `*` ou joker ignoré et journalisé ; `PermissionsForTest` |
| C12 | Faible | `sanitizeFilename` partiel, MIME du serveur transmis tel quel | **corrigé** : `ShareFilename` (séparateurs, `..`, caractères de contrôle, 100 caractères, MIME `type/sous-type` sinon `application/octet-stream`) ; `ShareFilenameTest` |
| C13 | Info | `librechat://model` pré-sélectionne endpoint et modèle sans confirmation | noté, sans action |

## 3. Points vérifiés sans constat

Jetons LibreChat au repos (AES-256-SIV/GCM, clé Keystore, récupération en
place, clés par compte, époque de jeton) ; rafraîchissement single-flight,
cookie et corps conformes, 429 avec `Retry-After` ; intercepteur d'auth (une
seule relance après 401, chemins d'auth sans bearer, identité « pending »
isolée) ; en-têtes de passerelle (portée schéma + hôte + port, retrait à
chaque saut, valeurs ASCII, masquage) ; redirections sans rétrogradation ;
détection de passerelle jamais relancée ; timeouts partout ; `Logging` à
`NONE` ; `LogRedactor` sur le fichier de diagnostic ; PKCE/`state`/PAR ;
`EngineGrantRefused` ne détruit la paire que sur 4xx ; manifeste (une seule
activité exportée, FileProvider non exporté aux chemins de cache, pas de
`debuggable`, release minifiée) ; deep links à résolveur unique ; WebView
`allowFileAccess=false`, `allowContentAccess=false`, erreurs TLS annulées ;
iOS TLS système, Keychain non synchronisé, flux borné par lecture ;
dépendances sans avis actif.

## 4. Ouvert, non bloquant

- **F2** — plafonner la section d'en-têtes et chaque ligne dans
  `HttpResponseParser`, `readUTF8Line(limit)` et plafond de `currentData`
  dans `SseLineParser` : déni de service local par un serveur défaillant.
- **F4** — faire échouer `assembleRelease` sans keystore (repli explicite
  par propriété), ou suffixer l'`applicationId`.
- **Épinglage de certificat par serveur** (M4, facultatif) : la table
  `servers` peut porter une empreinte ; `CertificatePinner` côté OkHttp,
  `sec_protocol_options_set_verify_block` côté NWConnection.
- **`cleartextTrafficPermitted`** reste `true` au niveau OS : la borne vit
  dans l'app. Passer à `false` couperait tout serveur LAN.
- **I3** — `security-crypto` 1.1.0 est déprécié ; migration à prévoir.
- **iOS** garde la base `cdn.jsdelivr.net` pour ses WebViews (hors périmètre de
  ce lot) ; le viewer plein écran d'images passe encore par le loader
  authentifié (même origine seulement, donc sans fuite, mais à aligner).
- **À vérifier sur appareil** : un artefact HTML et un React dans l'iframe
  sandbox (`frame-src about:`), un partage entrant, un lien `mailto`.

## 5. Méthode et limites

Lecture statique du dépôt ; pas de compilation locale (la CI est le
contrôle : detekt, tests unitaires, assemblage, tests iOS simulateur) ;
`upstream/` vide dans ce clone, donc l'attribut `SameSite` du cookie
`refreshToken` côté serveur n'a pas été vérifié ici. Aucun secret lu.
